# Контракты v0.1.0

`core.schema.json` задаёт предлагаемые внешние форматы Snapshot, EntityVersion, CodeUnit, Relation и ContextPackage. Сервис этих форматов ещё не реализован. Примеры в `examples/` проверяются JSON Schema и используют собственную fixture, а не данные работающей БД.

Каждый example обёрнут в `{ "schema": "имя определения", "value": { ... } }`. Обёртка нужна только документационному validator. Значение `value` соответствует выбранному публичному контракту.

Диапазоны `SourceSpan` — полуоткрытые интервалы bytes исходного blob. JSON Schema проверяет структуру и минимумы. Согласованность `end > start`, hashes, snapshot/foreign keys и типовых доказательств требует доменной проверки; она перечислена в [модели данных](../docs/DATA-MODEL.md).

Примеры source ranges и content hashes сверяются с [fixture](../fixtures/batching.py) локальной проверкой. Полнота ссылок на весь будущий ledger этими отдельными примерами не проверяется. `tokens_used=null` в package означает, что токенизация в этом контрактном примере не измерялась.

При несовместимом изменении формата повышать schema_version, сохранять миграционное объяснение и обновлять затронутые examples/API. Предложения модели сначала проходят этот формат, затем независимый admission.
