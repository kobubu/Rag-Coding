# Явная CM-first процедура

Отдельные 24 сессии: те же шесть задач, один повтор, обе группы и оба native клиента. Добавлено одинаковое условие в prompt обеих групп: если CM доступен, сначала focused retrieve с бюджетом около 6000 source bytes; иначе обычные repository tools. Остальные файлы, модели, grader и установленный CM 0.8.0 прежние.

Причина follow-up — отсутствие самостоятельных обращений к подключённому CM в стандартном Claude Code. Решение зарегистрировано в [guidance-plan.json](../guidance-plan.json) до завершения основной серии. Эти задачи уже использовались; follow-up не является новым held-out корпусом. Исходные 48 попыток сохранены отдельно, не заменяются вторым результатом.

Основной [runner](../../../scripts/client_ab.ts) исполняет и эту серию. Для повторения подготовить новый label, затем **до запуска моделей** задать в его частном `protocol.json` один repetition, те же точные model IDs и полный `prompt_suffix` из опубликованного протокола этой серии. После freeze `run-both` делает отдельную CM calibration, затем оба клиента. Нельзя менять активный протокол или отбирать удачные попытки. API-ключ поступает только через stdin контроллера.

[Общий протокол](../README.md) описывает ограничения времени, источников, проверки и token accounting. Результаты двух серий анализируются отдельно; одинаковая политика выбора инструментов внутри новой пары позволяет оценить эффект доступности CM при явном правиле его использования.
