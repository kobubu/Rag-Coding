# Нативные Codex / Claude Code: протокол CM A/B

Серия 15 октября 2026 года проверяет **установленный CM 0.8.0**, а не собственный упрощённый agent loop. Настоящие CLI сами выбирают инструменты, правят копии Geo Dash и заканчивают задачу. Основное сравнение — внутри каждого клиента: разные модели между клиентами не ранжируются.

После первых 72 попыток зарегистрирована [отдельная проверка исправления 0.8.1](fix-plan.json): ещё 24 свежие сессии с теми же задачами и условным CM-first правилом. Найденная несовместимость structuredContent сначала проверяется случайным неизвестным модели маркером при отключённых обычных file tools. Старые результаты сохраняются; новая серия не является held-out корпусом и не смешивается с прежними.

## До запуска

- Codex CLI 0.162.1, GPT-6 Luna, low reasoning, Windows MXC / workspace-write, approvals never. CLI установлен отдельно в `.artifacts/native-codex`; настройки desktop не менялись.
- Claude Code 2.1.288, `claude-sonnet-5-5`, low effort, штатный вход claude.ai, acceptEdits, ограниченный список обычных coding tools. Его стоимость — оценка CLI по прайсу, не подтверждённый денежный счёт.
- Оба клиента действительно изменили пробный файл и перечитали сохранённое значение. Оба вызвали настоящий CM MCP. Проверка обнаружения tools сама по себе недостаточна.
- Корпус: 502 текстовых source/test/config файла, в том числе 226 индексируемых JS-файлов. Копия готовой локальной проекции, MiniLM / LanceDB, adaptive / exact; первоначальное построение индекса в время сессии не входит.
- Шесть задач в [cases.json](cases.json), два повтора, обе группы, оба клиента: 48 сессий. Порядок CM/none меняется по задаче и повтору. Свежие непрозрачные имена каталогов одной длины; нет resume и одновременных измеряемых сессий.

## Что отличается между группами

CM: один штатный stdio MCP server из установленного пакета и сгенерированный installer project skill. None: MCP CM и его skill отсутствуют. Prompt, исходники, модель, effort, лимиты и обычные инструменты внутри клиента одинаковы. В основной серии агенту не приказывают вызвать CM: измеряется также фактическое использование подключённого плагина.

## Независимая оценка

Оценщик [client_checks.ts](../../scripts/client_checks.ts) находится вне доступной агенту рабочей копии. До серии каждый исходный вариант отклонён, а каждая отдельно подготовленная эталонная реализация прошла проверки. Это реальные задачи на исходном коде; искусственных поломок нет.

| Задача | Проверяется |
|---|---|
| stats-linear | Полная семантика статистики, NaN, смешанные ключи, порядок/ничьи, отсутствие мутаций; CPU ≥1,25× |
| wallet-deduplicate | Уникальность чеков, мусор/не-массив, конечные целые счётчики, монотонность и идемпотентность |
| quota-validation | Настоящая дата, точные слоты/сумма, clock rollback, два модуля, атомарный отказ |
| motion-extrema | Аналитические экстремумы синуса, знак, фаза, обе ориентации интервала, круг/прямоугольник |
| own-city-grants | Только собственные city IDs, три точки валидации, наследуемые имена, валидные форматы |
| compiled-input | Эквивалентный снимок интервалов, границы/перекрытия/обратные запросы, варианты, CPU ≥1,25× |

Дополнительно запускаются 33 существующих регрессии ads/economy/shared; хеши остальных исходных файлов должны остаться прежними. Для успеха нужны завершение клиента, код 0, поведенческие/CPU проверки, регрессии и соблюдение области изменений. Слова модели об успехе не являются оценкой. Неудачные валидные сессии включены в расход целиком.

CPU измеряется внешним процессом с чередованием baseline/candidate и медианой повторов. Для compiled-input построение учитывается отдельно от query CPU. Это не измерение FPS или прохождения всей игры.

## Время и токены

Время агента: от запуска CLI до выхода, включая model/tool turns, MCP startup и retrieval. Подготовка копии, готовой проекции и внешние проверки записываются отдельно; дополнительно считается checked time. Успешные сессии не выбираются отдельно ради лучшего среднего.

Здесь каждая задача начинается с нового процесса клиента и MCP. В длинной интерактивной сессии часть startup амортизируется, а история разговора растёт; такой режим отдельно не измерен. Лимиты серии: 240 секунд на session, 16 provider Responses calls на Codex run, $0,75 native Claude list-budget на run и отдельный API cost guard $2.

Codex: настоящий Responses API через аутентифицированный loopback forwarding; ключ остаётся в памяти контроллера. Счётчики CLI сверены с provider usage. `input_tokens` уже включает cache read/write, поэтому они повторно не прибавляются. Claude: итоговый native `usage`, где input/cache read/cache creation — отдельные категории. В обоих случаях показаны категории кеша и весь output. Сессии свежие, но глобальный provider cache не сбрасывается.

Расчёт GPT-6 Luna: uncached input $0,10, cache read $0,01, cache write $0,125, output $0,50 на миллион токенов; применяется в пределах обычного input tier. Источник — [официальная страница модели](https://developers.openai.com/api/docs/models/gpt-6-luna). Claude list estimate берётся из native final result.

Для времени/токенов — суммы, парные выигрыши и 10 000 bootstrap-перевыборок по шести задачам с сохранением двух повторов внутри пары. Маленькая выборка одного проекта не доказывает универсальный эффект.

## Отдельные диагностические попытки

Первую серию встроенного Codex 0.130.0-alpha.5 остановили: модель фактически получила read-only, хотя config задавал запись. Пять законченных диагностических сессий сохранены отдельно от основной серии, поскольку правка была недоступна. После включения unelevated backend команды зависали и в 0.130, и в 0.162.1. Работоспособность MXC доказана до новой основной серии реальной записью через модель. Настройка, пробы и известный их расход учитываются отдельно; часть прерванного in-flight расхода не восстановлена.

CM 0.8.0 во время серии не исправляется. Найденные contract/tool ошибки учитываются как ограничения проверяемой версии. Сырые ответы, чужой код, ключи и OAuth-коды не публикуются.

## Воспроизведение

Текущий [runner](../../scripts/client_ab.ts) настроен на Windows test stand с установленным `D:/CodeMemory` и исходным `D:/Geo Dash`. Перед другой машиной надо адаптировать пути; это исследовательский runner, а не installer API. Зависимости и клиенты закреплены. В свежей серии использовать новый label:

```powershell
npm run build:core
node dist/scripts/client_ab.js prepare codex new-label
```

Перед платной серией нужны успешные native write/CM probes и зафиксированные hashes протокола. `run-both all new-label` читает API-ключ одной строкой stdin, держит его только в памяти и последовательно запускает Claude и Codex. Не передавайте ключ аргументом команды и не сохраняйте его в shell history. Анализ: `node dist/scripts/summarize_client_ab.js new-label`. Частные артефакты — `.artifacts/client-ab-<label>`, публичные агрегаты — этот каталог.
