# Поиск и восстановление контекста

## Режимы запроса

| Режим | Пример | Основные источники |
|---|---|---|
| Адресный | Путь, qualified symbol, выбранное употребление | Точные индексы и определение |
| По действию | «Где очищается накопитель?» | Текст, роли units, embeddings |
| Влияние | «Кто использует этот параметр?» | Разрешённые ссылки, contracts и обратные связи |
| Пример | «Как здесь добавляют обработчик?» | Подходящие реализации и принятые решения |
| Обзор | «Как устроена обработка платежа?» | Точки входа, пути, версионные сводки модулей |
| Сравнение | «Что изменилось между двумя версиями?» | Явно выбранные два snapshot и lineage |

## Pipeline

1. **Зафиксировать область.** Repository, snapshot или явно выбранные snapshots, режим, путь/язык и access scope. История включается только по выбранному режиму.
2. **Найти anchors.** Прямой символ или путь имеет приоритет. Текстовый индекс добавляет части `camelCase`/`snake_case`; точное имя и регистр сохраняются отдельно.
3. **Получить кандидатов.** Использовать точный, полнотекстовый и при наличии векторный поиск. Каждый канал возвращает kind, source, snapshot и score своего типа.
4. **Объединить и пересортировать.** Начальный вариант RRF или прозрачные ранговые правила выбирается на evaluation. Несопоставимые score не складываются как общая вероятность.
5. **Выбрать детализацию.** Взять функцию, блок или точную аннотацию по задаче. Родитель и его дети из одного участка не получают независимый вес дубликатов.
6. **Восстановить окружение.** Получить внешние bindings, типы, guards и lifecycle-owner; для задачи влияния — потребителей и contracts. Граф обходится по нужным predicate и направлению.
7. **Собрать ContextPackage.** Удалить повторные spans, сохранить зависимости, оценить tokens заданным tokenizer. Важный container не обрезается молча посередине.
8. **Вернуть источники и ограничения.** Причины выбора, актуальность, diagnostics, исключённые зависимости и их причины видимы клиенту.

Жёсткие ограничения snapshot и доступа применяются до формирования контекста. Особенности approximate-индекса и фильтров должны быть проверены по полноте выдачи, а не компенсированы извлечением чужих текстов.

## Context closure

Для каждого выбранного unit обходятся обязательные ContextRequirement. Если нужный source отсутствует, dependency остаётся в omissions с причиной. Сервис не заявляет пакет полным по одному успешному обходу.

Для объяснения выражения часто достаточно определения символа и условия. Для правки nested function может потребоваться весь родитель. Для изменения сигнатуры добавляются найденные реализации и употребления; для изменения контрактного поля — сериализация и известные потребители.

Начальная глубина графа ограничена 1–2 переходами, но это бюджетная политика. Большие циклы, общие utility-узлы и массовые callers ограничиваются отдельно. Пакет может показывать «найдено 120 потребителей, включены 8, остальные перечислены ссылками» с точным основанием счёта.

## Бюджет и порядок

Порядок пакета: задача и область → основные исходники → обязательное окружение → contracts → проверки и решения → кандидатные пояснения. Сводка не подменяет недоступный source.

При недостаточном бюджете удаляются менее релевантные необязательные примеры. Обязательная зависимость либо включается целиком, либо явно отмечается как отсутствующая. Клиент может запросить более широкий пакет. Для model-backed ответов budget учитывает системные инструкции и резерв ответа отдельно от размера найденного кода.

## Обоснование выдачи

Каждый item содержит выбранный unit/span, его role, retrieval channel, evidence и короткий reason. «Высокая cosine similarity» — технический score, а не доказательство применимости. Candidate relation отображается как кандидатная. Неполное разрешение вызовов сохраняет diagnostics в ответе.

Кеш ключуется snapshot, access scope, режимом, запросом, версиями ранжирования и контекстного алгоритма. В командном режиме нельзя переносить пакет из общей cache-области пользователя с более широкими правами.

## Память решений

SolutionCase возвращается с условиями применения: язык, версии библиотек, контракт, предыдущее изменение и фактические проверки. Даже принятый пример проверяется на совместимость с текущим snapshot. Пара «до/после» не смешивается с текущим исходным кодом как ещё одна актуальная реализация.

Метрики проверки pipeline и контрольные запросы находятся в [EVALUATION](EVALUATION.md).
