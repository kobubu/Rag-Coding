# Экономичность CM в агентской сессии

Документ описывает, как CM (Code Memory) снижает расход агента, какие изменения внесены после 0.8.1 и как они проверены живыми сессиями DeepSeek Harness с GPT-6 Luna на Geo Dash. Все прогоны, включая неудачные, сохранены в [evaluation/efficiency](../evaluation/efficiency).

## Откуда берётся расход агента

Агент работает циклом: вызов модели → инструмент → вызов модели. При каждом вызове модели заново отправляется вся переписка: системный промпт, схемы инструментов, задача и всё, что уже прочитано. Поэтому

**токены сессии ≈ число вызовов модели × размер переписки.**

Каждый лишний `read`, `grep` или `glob` стоит целого вызова. Прочитанный файл к тому же остаётся в переписке и повторяется во всех следующих вызовах. CM экономит, когда модель с первого шага получает нужный код и правит без поиска и перечитывания. Минимум для правки с проверкой — три вызова: правка, `project_checks`, итог.

## Как CM формирует контекст

Перед первым шагом агента plugin берёт текст задачи и строит один блок контекста, не больше 6 000 байт исходника:

1. **Один названный небольшой самостоятельный файл** (до 6 000 байт, без import) — отдаётся целиком прямо с диска, индекс не нужен.
2. **Названные функции** (`` `creditAdReward` ``, путь к файлу) — точные якоря в графе компилятора и ограниченное замыкание зависимостей.
3. **Поиск неизвестного места** — лексический IDF, локальные MiniLM-векторы и поддержка соседей в графе.

Код проверяется по версии файла и регистрируется в Harness как прочитанный, поэтому правка возможна без отдельного `read`. Подробно маршруты описаны в [графе и бюджете контекста](GRAPH-BUDGET.md) и [скорости 0.7.0](SPEED-TOKENS.md).

## Что изменено

### Этап 1 — поиск и выдача (коммит `1a6b157`)

| Было в 0.8.1 | Стало | Зачем |
|---|---|---|
| Запросом служил весь текст сообщения, включая общие инструкции агента («работай только в этом workspace», «закончи итогом») | `focusQuery` ([focus.ts](../src/code-memory/focus.ts)) убирает предложения, в которых ≥80% слов — общая лексика процесса; предложения с путями, `` `именами` `` и camelCase остаются всегда | В пилоте инструкции увели поиск motion-envelope в 9 посторонних файлов `geoOriginal*`; без них первым находится `geoCollisionCandidates.js` |
| Короткие файлы отдавались фрагментами | Файл до 3 000 байт целиком, с пометкой `(whole file)`, если позволяет бюджет | Фрагмент короткого файла провоцирует «проверочный» `read` |
| Блок начинался «partial» и всегда заканчивался «read if necessary», даже при 0 пропусках | Заголовок говорит, что код актуален и уже засчитан как прочитанный; предложение дочитать — только если что-то действительно пропущено | В quota-receipts модель видела обе строки с ошибкой, но перечитала оба файла |

### Этап 2 — меньше повторов (коммит `7d1d605`)

| Изменение | Как устроено |
|---|---|
| **Повторный `read` не дублирует файл** | Хук Harness `tools/post-execute` (официально позволяет заменить результат инструмента). Если модель читает файл, который CM уже показал целиком, и его байты не изменились (сверка SHA-256), вместо копии возвращается короткая ссылка на контекст выше. Только первый повтор; второй `read` и любой изменённый файл отдаются как обычно. Подмены пишутся в диагностику событием `read_deduplicated`. Переписывать сообщения в `llm/stream` нельзя: Harness замораживает запрос, собранный циклом, чтобы сессия восстанавливалась из лога |
| **Места вызова в контексте** | Строка `Call sites of creditAdReward: game/src/platform/rewarded-flow.js:34.` строится из связей `calls` индекса, включая вызовы на уровне модуля (их граф функций раньше терял). Если вызовов нет, так и написано. Модель чаще всего шла в `grep` именно за этим |
| **Конкретнее инструкция** | В системном промпте: файлы `(whole file)` полные, не перечитывать; места вызова уже даны; правку в 1–2 местах делать сразу без отдельного плана |

`todo_write` не трогался: это настройка Harness, она одинакова для всех вариантов и улучшила бы и вариант без CM.

## Методика

- **Проект:** Geo Dash, тот же commit `1700732`, что в серии 0.7.0; corpus — 224 отслеживаемых JS-файла, 7 503 строк векторов.
- **Задачи:** шесть спецификаций [0.7.0](../evaluation/speed-tokens/cases.json): именованные исправления, цепочка зависимостей, два поиска неизвестного места, контракт двух модулей и CPU-оптимизация. В каждую рабочую копию внесена ошибка; исходное поведение проходит проверку, испорченное — нет.
- **Варианты:** `none` — без CM; `cm_base` — замороженная сборка 0.8.1; `cm_next` — текущая сборка. Одинаковые модель (`gpt-6-luna`, reasoning low), инструменты, лимиты (12 вызовов, 240 с) и подготовленные индексы.
- **Порядок:** вариантов внутри задачи чередуется по кругу и в обратную сторону; идентификаторы запусков непрозрачные.
- **Качество:** независимый grader вне Harness с другим seed, проверка экспортов, отсутствие лишних изменений и новых файлов. Для оптимизации — реальное ускорение функции не меньше 1,25×.
- **Учёт:** токены и стоимость берутся из usage провайдера по каждому вызову; цена рассчитана по тарифам Luna с кешем (это оценка, не счёт). Время — от запуска Harness до закрытия, без копирования и итоговой проверки.
- **Заморозка:** перед платным прогоном протокол фиксирует хеши кода CM, runner, grader, входов и Harness. Изменение кода во время серии прерывает её.

Runner: [efficiency_ab.ts](../scripts/efficiency_ab.ts), запуск — [run_efficiency_ab.ts](../scripts/run_efficiency_ab.ts), сводка — [summarize_efficiency.ts](../scripts/summarize_efficiency.ts).

## Ограничения

- Один проект, шесть задач, два повтора на вариант; разброс поведения модели сопоставим с эффектом на отдельных задачах. Это не статистическое доказательство и не обещание того же выигрыша на других проектах.
- Индексы и векторы строились заранее и не входят во время сессии; первая постройка и полная пересборка — отдельная стоимость.
- Подмена повторного `read` полагается на то, что контекст CM остаётся в переписке; при сжатии истории в длинной сессии указатель может ссылаться на вытесненный текст. Поэтому подменяется только первый повтор.
- Места вызова берутся из связей компилятора по JS/TS; динамические вызовы (по строке, через события) не видны.

## Как повторить в облачной сессии Claude Code

1. Сетевой секрет окружения: тип Bearer, сайт `api.openai.com`, значение — ключ OpenAI. Ключ подставляет прокси, в контейнер он не попадает; скриптам достаточно любого непустого `CM_AB_API_KEY`.
2. Зависимости. Postinstall `onnxruntime-node` пытается скачать CUDA-библиотеки с nuget, прокси облака рвёт это соединение; для CPU они не нужны:
   ```bash
   ONNXRUNTIME_NODE_INSTALL=skip npm ci
   npm run verify
   ```
3. Harness отдельно от проекта:
   ```bash
   mkdir -p ~/harness-rt && cd ~/harness-rt && npm init -y
   ONNXRUNTIME_NODE_INSTALL=skip npm i @deepseek-ai/dsh@0.2.0-rc.2 @deepseek-ai/dsh-base@0.2.0-rc.2
   ```
4. Geo Dash — checkout commit `1700732`; сборка CM для сравнения — копия `dist` нужной версии.
5. Подготовка (без вызовов модели), заморозка и прогон:
   ```bash
   C="--project ../geodash --out ../exp/run1 --harness ~/harness-rt/node_modules/@deepseek-ai/dsh/lib/bin.js \
     --cases evaluation/speed-tokens/cases.json --model-cache .code-memory/models --reuse-cache empty-cache.json \
     --base-plugin ../cm-base/dist/src/harness/plugin.js --arms none,cm_base,cm_next --repetitions 2"
   npm run harness:efficiency -- --phase prepare $C
   P=$(npm run -s harness:efficiency -- --phase freeze $C | tr -d '"')
   CM_AB_API_KEY=proxy-injected npm run harness:efficiency -- --phase run --protocol $P $C
   node dist/scripts/summarize_efficiency.js ../exp/run1/results-none+cm_base+cm_next.json summary.json
   ```
   `empty-cache.json` — `{"embedding": <EMBEDDING из vector.ts>, "values": {}}`. Подготовка шести задач занимает около четырёх минут на CPU.
