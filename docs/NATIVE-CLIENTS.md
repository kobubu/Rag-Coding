# CM в Codex и Claude Code

Раньше CM подключалась к Codex и Claude Code только как MCP-сервер, и экономии не было: модель сама решала, вызывать ли CM, вызывала редко, а вызвав, всё равно читала файлы ([HISTORY.md](HISTORY.md#7-codex-и-claude-code-через-mcp)). Теперь в оба клиента CM подаёт контекст так же, как в Harness: до первого вызова модели, через хук `UserPromptSubmit`.

## Как подключается

`cm-hook` ([src/hooks/cli.ts](../src/hooks/cli.ts)) получает от клиента событие с текстом задачи, выбирает контекст тем же сервисом, что и MCP-сервер, и возвращает `hookSpecificOutput.additionalContext`: инструкцию и блок `CM context`. Формат общий для Codex и Claude Code. Заголовок не утверждает, что файл «засчитан как прочитанный»: эти клиенты не регистрируют чтение по внешнему контексту. При ошибке хук ничего не добавляет и не мешает запросу.

Codex, `~/.codex/config.toml` или `<repo>/.codex/config.toml`:

```toml
[[hooks.UserPromptSubmit]]

[[hooks.UserPromptSubmit.hooks]]
type = "command"
command = "node /path/to/dist/src/hooks/cli.js --project /path/to/project --retrieval-policy adaptive --auto-update true"
timeout = 120
```

Claude Code, `.claude/settings.json`:

```json
{ "hooks": { "UserPromptSubmit": [ { "hooks": [ { "type": "command",
  "command": "node /path/to/dist/src/hooks/cli.js --project /path/to/project --retrieval-policy adaptive --auto-update true", "timeout": 120 } ] } ] } }
```

Аргументы те же, что у MCP-сервера ([MCP-SETUP.md](MCP-SETUP.md)): `--index`, `--vectors`, `--model-cache`, `--memory-dir`, `--embedding-cache`, `--source-scope`. Оба клиента требуют доверить хук: Codex — через `/hooks` (в автоматических прогонах `--dangerously-bypass-hook-trust`), Claude Code — как обычные настройки проекта. Переменная `CM_HOOK_LOG` пишет диагностику без исходного кода: маршрут, файлы, размер, время. Повторный запуск хука на Geo Dash в маршруте поиска места (с загрузкой векторной модели) занимает около 3,3 с.

## Методика

Те же шесть задач Geo Dash, рабочие копии, векторы и независимый грейдер, что в сериях Harness ([EFFICIENCY-AB.md](EFFICIENCY-AB.md)); раннер [native_ab.ts](../scripts/native_ab.ts). Три варианта, два повтора, порядок чередуется:

- **без CM**;
- **CM 0.8.1** — как его ставил прежний установщик: MCP-сервер и skill, модель решает сама;
- **новый CM** — хук плюс MCP-сервер и skill из текущей сборки.

Публичная проверка (`project_checks`) дана всем вариантам одинаково — как команда вне рабочей копии. Codex: `gpt-6-luna`, reasoning low, песочница workspace-write; расход — из событий `turn.completed`, цена — расчёт по тарифам Luna. Claude Code: Sonnet 5.5, `--permission-mode acceptEdits`, разрешены Read/Edit/Write/Grep/Glob и только команда проверки; загружаются лишь MCP и хук эксперимента (`--strict-mcp-config`, `--setting-sources project`), без переменных родительской сессии; расход и цена — из итогового события Claude Code. Активация хука подтверждается логом в каждой сессии нового CM, иначе серия останавливается.

### Пробные прогоны

Перед сериями — по одной сессии на задаче motion-envelope в каждом клиенте ([Codex](../evaluation/native/codex-pilot-results.json), [Claude Code](../evaluation/native/claude-pilot-results.json)): новый CM −65% и −57% токенов к варианту без CM.

## Ограничения

- Одна серия на клиент, шесть задач одного проекта, два повтора.
- Claude Code проверен только с Sonnet 5.5; Codex — только с GPT-6 Luna.
- Подмена повторного чтения из Harness здесь не используется: в Codex файлы читаются командами shell; для Read в Claude Code такая замена не проверялась.
- В обоих клиентах экономия меньше, чем в Harness (−30…−42% против −45…−66% токенов), и выигрыш по суммарному времени не устойчив.
