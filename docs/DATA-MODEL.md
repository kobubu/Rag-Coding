# Модель данных и версионирование

## Основные записи

| Запись | Ключевые поля | Инвариант |
|---|---|---|
| Repository | repo_id, identity, access_scope | Локатор не заменяет идентичность репозитория |
| Snapshot | snapshot_id, repo_id, base_commit, overlay_hash, analysis_config_hash, state | Запрос фиксирует один согласованный снимок |
| Blob | blob_id, sha256, raw_bytes, encoding, size | Исходные bytes неизменяемы |
| SnapshotFile | snapshot_id, path, blob_id, classification | Один путь однозначно указывает версию файла в снимке |
| Scope | scope_id, owner, parent_scope_id, kind | Вложенность областей не выводится из совпадения имён |
| EntityVersion | entity_id, semantic_key, name, kind, scope_id, definition_spans | Символ может иметь несколько определений, например partial-тип |
| Occurrence | occurrence_id, span, entity_id или null, resolution_status | Неразрешённое употребление не получает выдуманный target |
| CodeUnit | unit_id, parent_unit_id, span, content_hash, kind, search_role | Исходник читается по span из соответствующего blob |
| ContextRequirement | unit_id, target, kind, evidence, resolution_status | Требование может быть установленным или неизвестным |
| Annotation | subject, span, payload, origin, status, fingerprint | Объяснение не заменяет код |
| Relation | from_id, to_id, predicate, origin, status, evidence | Тип и направление определены контрактом |
| AnalysisRun / Job | snapshot, stage, fingerprint, lease, attempt, result | Состояние выполнения отделено от статуса знания |
| Concept / SolutionCase | понятие или задача, evidence, applicability, verification | Ручные решения имеют отдельную историю |
| ContextPackage | snapshot, items, evidence, budget, omissions, diagnostics | Пакет объясняет свою полноту и ограничения |

JSON Schema и примеры первого публичного контракта находятся в [contracts](../contracts/README.md). Полная SQL-модель вводится отдельной задачей и должна сохранять эти инварианты.

## Диапазоны исходника

Канонический диапазон — полуоткрытый интервал `[start_byte, end_byte)` **в исходных байтах blob**. Обе границы относятся к одному файлу; начало меньше конца, конец не превышает размер. Строки и столбцы вычисляются для интерфейса и не используются как ключ.

Позиции TypeScript Compiler API относятся к UTF-16 code units строки, а не к bytes исходника. Mapping переводит их в исходный blob с учётом Unicode, surrogate pairs, BOM и CRLF. Текущий TS probe поддерживает точный UTF-8 и отклоняет некорректные bytes или границу внутри surrogate pair. Для Python AST координаты столбца относятся к UTF-8 представлению парсера; для файлов с иной исходной кодировкой нужен отдельный явный mapping. Сохраняются исходные bytes и представление для анализа; отсутствие точного преобразования приводит к диагностике, а не приблизительному диапазону.

CRLF, BOM, Unicode, комментарии и промежутки нельзя терять при восстановлении исходника. Применение патча сравнивает хеш файла, а не только показанные номера строк. Обязательные проверки диапазонов перечислены в [EVALUATION](EVALUATION.md).

## Идентичность

Версионные ID — непрозрачные детерминированные значения. Для `unit_id` допустима схема UUIDv5 по `repo_id`, `snapshot_id`, пути, владельцу/структурному адресу, виду записи, диапазону и версии segmenter. `content_hash` считается отдельно по точным bytes.

Одинаковый текст в двух местах имеет разные записи. Хеш содержимого позволяет повторно использовать совместимый embedding, но не объединять разные употребления. Для символа используются semantic key анализатора и область видимости; для локального символа без semantic key — адрес определения в структуре снимка.

При смене snapshot ID сущностей меняются. Возможная преемственность после перемещения или переименования хранится отдельным lineage-отношением с доказательствами и статусом. Автоматическая преемственность не считается гарантированной.

Библиотека задаётся экосистемой, именем, разрешённой версией и, если доступно, digest. Поле зависимости из manifest без разрешённого lock-файла помечается как requested_version, а не установленная версия.

## Версии и отпечатки

Snapshot фиксирует base commit и manifest overlay: добавленные, изменённые и удалённые файлы с хешами. Имя ветки — изменяемый указатель. Для нескольких репозиториев ContextPackage позже фиксирует составной manifest их версий.

`analysis_fingerprint` включает собственный blob, используемые dependency hashes, настройки сборки, capabilities и версии анализатора, segmenter, схемы и admission policy. Для модельного результата добавляются model, prompt и провайдерная конфигурация без секретов.

Свежесть сводки зависит от всех её доказательств. Изменённый внешний тип инвалидирует использовавшую его аннотацию даже при неизменном коде блока. Embedding исходного текста и embedding зависимого описания имеют разные ключи кеша.

## Статусы

Состояние snapshot: `building`, `ready`, `failed`, `superseded`. `ready` означает согласованный опубликованный набор доступных capabilities; неполный семантический анализ отображается отдельно.

Состояние job: `queued`, `running`, `succeeded`, `retryable_failed`, `failed`, `cancelled`. Наличие успешного job не означает человеческого подтверждения знаний.

Статус знания: `derived`, `candidate`, `reviewed`, `rejected`, `stale`. `derived` обязательно содержит имя анализатора и границу его возможностей. `reviewed` сохраняет историю подтверждения. Новый модельный результат не перезаписывает ручное подтверждение молча.

## Хранение и индексы

Основные SQL-ограничения: принадлежность к snapshot, внешние ключи, уникальность occurrence в версии, допустимые типы записей и полей, диапазоны и отсутствие циклов parent-иерархии. Граф обычных зависимостей может содержать циклы.

Индексы: точное имя и квалифицированное имя, путь, scope/owner, исходящий и входящий predicate, fingerprint, состояние и lease job. Поисковые projections имеют собственную версию и контроль полноты. Удаление файла из нового снимка не удаляет его из истории автоматически.

Набор нескольких исходных участков хранится как bundle с упорядоченными ссылками. Он не маскируется под один непрерывный CodeUnit.
